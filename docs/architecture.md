# 架构与边界

当前实现为可复用核心 + CLI。插件宿主未确定，业务逻辑不依赖微信客户端或界面框架。

```text
用户授权的数据源 → 导入适配器 → 标准消息列表
                              ├─ JSON / Markdown 导出
                              ├─ 会话 / 日期目录 + 统计
                              ├─ 模型提供商 → 摘要 / 话题树
                              └─ 图片消息 → ICS
本地照片目录 → EXIF 适配器 ──────────────────┘
```

## 模块

- `core.py`：格式校验、按真实时间排序、目录、统计和标准导出。
- `photos.py`：只读照片 EXIF；不使用文件修改时间冒充拍摄日期。
- `providers.py`：Ollama 的显式请求入口，禁止重定向和默认代理转发。
- `cli.py`：输入/输出协调、会话与日期过滤，不覆盖已有文件。

## 下一步适配器约定

导入器输出 `core.normalize` 接受的消息列表，应保留稳定消息 ID、原始时间及来源信息。新增格式前提供脱敏样例与兼容性测试；不宣称未验证的微信版本可用。当前 JSON 格式是本项目格式，不是假定微信自带 JSON 导出。

未来界面和插件都调用核心，避免重复实现导出。未来云模型提供商必须明确展示待发送内容范围并安全存储密钥。照片 OCR/视觉提取的日期与事实需要用户核验；EXIF 拍摄日期也不能自动等同于照片中活动的发生日期。

目录树是确定性的会话/日期索引；AI 话题树是模型生成文本，目前没有结构化主题编辑器。首次迭代不包括微信数据库解密、进程注入、自动读取他人记录或自动上传档案。
