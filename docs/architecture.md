# 架构与边界

当前实现为可复用核心 + CLI + 独立本地浏览器界面。产品方向确定为本地应用，后续封装桌面安装包；业务逻辑不依赖微信客户端或界面框架。

```text
用户授权的数据源 → 导入适配器 → 标准消息列表
                              ├─ JSON / Markdown 导出
                              ├─ 会话 / 日期目录 + 统计
                              ├─ 模型提供商 → 摘要 / 话题树
                              └─ 图片消息 → ICS
本地照片目录 → EXIF 适配器 ──────────────────┘
```

## 模块

- `core.py`：格式校验、按真实时间排序、目录、统计和标准导出。
- `photos.py`：只读照片 EXIF；不使用文件修改时间冒充拍摄日期。
- `providers.py`：Ollama 的显式请求入口，禁止重定向和默认代理转发。
- `cli.py`：输入/输出协调、会话与日期过滤，不覆盖已有文件。
- `server.py`：只绑定回环地址的 HTTP 服务，固定静态资源路由，来源/Host/令牌校验和请求大小限制；默认在导入完成前写入本地档案。
- `storage.py`：独立 JSON 档案库，默认位于 `~/Documents/WeChatMemory`，可通过 `--data-dir` 自定义。标准化消息的 SHA-256 作为文件名，重复导入复用既有文件；临时文件写入并 fsync 后原子发布，不覆盖已有档案。文件权限 0600，加载时校验内容摘要；损坏文件保留并在列表返回错误。
- `web/`：聊天浏览、筛选、导出、月历与本地模型界面。导入时发送到同机服务验证及保存，刷新时读取最新档案，可切换历史档案；所有档案接口沿用会话验证，无云端托管。未实现删除接口；关闭视图不会删除文件。附件仅保存路径引用，未自动复制原文件。
- `importers.py`：已导出文件的兼容层，支持标准 JSON、she-love-me、常见 weflow-cli/CipherTalk 字段和时间戳 Markdown。时间转换与缺失字段提示可回查，格式错误整次失败；原始内容保留在首次导入档案中。
- `bundles.py`：用户点击后将完整档案按会话导出到独立目录，可复制指定附件根目录内的实际文件。基于内容散列去重，清单记录已复制/未复制原因；使用临时目录构建后一次性发布，失败不会留下被误认成完整备份的目录。离线 HTML 转义所有消息，图片只引用复制后的资源，不依赖 CDN。

备份包的 `messages.json` 使用可移植附件引用；原始路径和无法复制的引用在 `archive-original.json`、`attachments-manifest.json` 保留。`stats.json` 使用全量消息，`analysis_prompt.txt` 使用明确标注覆盖范围的均匀样本，与直接调用本机模型的既有功能分开。

## 桌面版路径

后续可在独立进程中启动现有回环服务，再由桌面 WebView 加载其界面。打包时必须包含 `web/` 资源；停止窗口时关闭后台服务。下一阶段评估原生文件选择、服务生命周期、签名与安装更新，目前不把浏览器界面称为原生桌面安装包。

支持 `document.modelContext` 的浏览器可选注册 `filter_chat_view`，复用可见搜索，只返回匹配数量，不调用模型。未支持时普通界面不受影响。当前环境没有可验证此提案 API 的浏览器上下文，该集成未做实际浏览器验证；HTTP 接口由测试覆盖，界面已做 JavaScript 语法检查，尚未进行浏览器交互和视觉回归测试。

## 下一步适配器约定

导入器输出 `core.normalize` 接受的消息列表，应保留稳定消息 ID、原始时间及来源信息。新增格式前提供脱敏样例与兼容性测试；不宣称未验证的微信版本可用。当前 JSON 格式是本项目格式，不是假定微信自带 JSON 导出。

未来界面和插件都调用核心，避免重复实现导出。未来云模型提供商必须明确展示待发送内容范围并安全存储密钥。照片 OCR/视觉提取的日期与事实需要用户核验；EXIF 拍摄日期也不能自动等同于照片中活动的发生日期。

目录树是确定性的会话/日期索引；AI 话题树是模型生成文本，目前没有结构化主题编辑器。首次迭代不包括微信数据库解密、进程注入、自动读取他人记录或自动上传档案。
